# Rebuild architecture

Status: the first application increment and subsequent context-coordination implementation use these responsibility boundaries. EVT-1068, EVT-1107 and EVT-1166 consolidated the initial direction; the adopted [context-coordination design](design/CONTEXT_UPDATE_COORDINATION.md) supplies the later commitment and recovery rules. Earlier Pi-first and LangChain `create_agent` recommendations remain documented with their corrections. [CURRENT_STATE](CURRENT_STATE.md) separates implementation from verified scope.

For shared terms, an end-to-end example and the module-specific engineering explanations, read [DEVELOPMENT_GUIDE](DEVELOPMENT_GUIDE.md). It links to detailed local guides. Source IDs provide optional provenance. They are not prerequisites for understanding this architecture.

## Responsibilities

| Component | Owns | Boundary |
| --- | --- | --- |
| Desktop shell | Task configuration, source/scope selection, progress, saved-document reading, intervention and export access | Electron/TypeScript/React. Reconstruct the UI from durable state after reconnect. |
| Python controller | Agent loop, finite execution policy, task lifecycle and accepted tool-batch sequencing | One controller and shared tools. The agent chooses conversion methods. |
| Small LangGraph StateGraph | Explicit model/tool/context/recovery transitions and checkpoints of compact orchestration state, including the current policy projection | Restores committed application effects; the framework does not decide a second policy truth or transact external effects |
| Context revision composer | Structural validation, exact source selections, ordered whole-batch candidates and explicit reuse on a named current base | Saving valid intent is not admission; one invalid context call prevents partial context application without undoing other tools |
| Context planner and coordinator | Actual protocol projections/costs; separate candidate disposition, formal policy commitment and executable continuation | Whole-candidate admission, necessary-cost proof and compaction feasibility answer different questions; one coordinator commits effects |
| Nexus request service | Native encoding of the context-selected frozen input, request identity, attempts, durable receive observations, complete accepted replies, budgets and cancellation checks | Normal reasoning and compaction share this service. It does not independently reselect evidence. |
| Attempt-local stream decoder and waiting policy | SSE framing/native assembly and first-progress/idle/optional-total clock decisions | Neither component executes tools, accepts a handoff, changes context policy or joins different attempts. |
| Shared tool dispatcher | Tool discovery, raw argument retention, validation, dispatch and durable original receipts | App-internal and external MCP/CLI surfaces use the same core contracts |
| Document/evidence core | Immutable source/evidence/candidate/version content, exact reads, editing, rendering and explicit-version exports | Assess content fidelity against the source. Storage integrity is a separate guarantee. |
| SQLite metadata | Version registration, current pointers, operation uniqueness/receipts and defined execution metadata | Short transactions cover durable metadata. Large immutable files remain external. |

There is no required module count or table count. Boundaries may share a file or be factored into packages as implementation warrants. Do not create a second agent loop merely to adopt a framework.

Streaming retains the same model and compaction nodes. `StreamDecoder` assembles one protocol response from one attempt and distinguishes substantive content from transport/lifecycle events. `RequestWait` evaluates that request's frozen policy; a late event cannot revive an expired wait. Nexus preserves decoded raw SSE chunks before interpretation, checkpoints receive observations and links the final raw stream to its separately assembled native response. Only complete native validation creates `accepted_response`; Runtime still executes solely from that accepted record. Graph checkpoints do not grant another network attempt or turn fragments into tools. [The waiting contract](CONTRACTS.md#streaming-progress-waiting) defines defaults, legacy frozen-request behavior and failure recovery; [route evidence](reference/NEXUS_STREAMING_SIGNALS.md) qualifies actual upstream capabilities.

## Agent loop and autonomy

Context coordination is part of that same loop. `ContextRevisions` captures each call without activation, then saves the final ordered batch candidate. `Context` builds native normal/compaction projections and their costs. `ContextUpdates` owns validity, disposition, policy commitment and continuation selection at an unfrozen boundary. Runtime writes the resulting graph projection. This separates the question “may this candidate still apply?” from “can the next request deliver its result?”. Confirmed necessary-content excess commits `needs_agent_revision` independently of diagnostic availability; only history pressure or explicitly unknown conditions retain an eligible wait. A later capacity increase cannot reverse that disposition. [Q2](CONTRACTS.md#q2-context-transitions) owns schemas, ordering and recovery.

The planner preserves different inputs for different questions. Complete admission uses the candidate, settled history/handoff and exact prospective applied result. Necessary-cost proof retains mandatory active/candidate material and real protocol/schema/image/output costs, while excluding reducible history and optional result presentation; a low bound is not proof of complete fit. Compaction measures its own active-policy view and summary instructions. Final-handoff acceptance previews the actual target continuation and specific outcome. Unknown-outcome reserves remain bounded planning allowances. Shared profitable-reference projection excludes substitutions that enlarge input, while each caller still measures its own native envelope. This replaces the old normal-template gate on compaction and inconsistent reserved-versus-specific settlement previews.

A graph can express a dynamic model/tool loop. Graph-based execution does not require a fixed business workflow, and autonomy does not remove the need to manage state, budgets, side effects and recovery. The graph represents execution responsibilities. The model still selects methods, tools and continuation based on results.

The model selects source access, OCR, scripts and reconstruction scope. The app checks capacity, maintains identities and accepts complete native replies. The dispatcher executes only validated calls. Before the assembler builds the next model input, the dispatcher records each accepted batch member's success, rejection or failure. A complete accepted reply does not imply that every proposed operation passes domain validation. Context work occurs at a defined safe boundary with the same durable request and budget handling as other model calls.

The implemented graph has `coordinate`, `prepare`, `model`, `tools`, and `compact` nodes. `tools` executes/reconciles accepted calls sequentially and always returns through `coordinate`, including a batch containing `report`. The coordinator restores committed effects, settles the whole context candidate or checkpoints an eligible wait. A valid report can then end the invocation locally; it does not require another model call. Otherwise `prepare` freezes a fitting actual normal/compaction request through Nexus. Text-only replies return with durable continuation feedback; invalid handoffs use bounded correction while old history remains active. Stop before the batch completes preserves captures without applying a partial context revision. Cancellation and exhausted limits retain their existing gates. [The contracts](CONTRACTS.md#implemented-first-version-contracts) own exact state and recovery behavior.

Continuation has an explicit entry boundary. The server conveys Continue; the runtime reconciles durable records before resuming a request or recording a distinct request transition. Nexus owns accepted-reply/attempt facts, the dispatcher owns original tool receipts, the context catalog commit owns policy/disposition effects, and graph state owns the next step and corresponding projection. Direct Continue resumes the accepted batch. New amendments retain committed effects, supersede uncommitted context revisions and skip unstarted old calls; they do not relabel unknown local outcomes or rewrite source instruction bases. Explicit reuse creates a new revision rather than reviving the old candidate. This uses the existing single task writer and preserves method choice.

The separate **Resume context organization** action carries an exact unknown-compaction request ID. The server validates that ID against the current graph position under the task lock. Runtime uses the existing immutable continuation receipt and event identity to commit one chosen successor transition before the graph advances; Nexus does not mutate the old replay policy. Reopening recovers an already committed choice, while ordinary Continue cannot invent a new one. This narrow manual recovery addresses an observed user pause during compaction; it does not generalize unknown normal-model or local-tool recovery. [Q3](CONTRACTS.md#q3-execution-recovery-and-delivery) owns the conditions and uncertainty.

Task settings and time accounting remain application-service facts outside graph rollback. The server validates allowed changes under the task lock and records before/after settings with the job update. Nexus separates current total allowances from frozen request input/replay policy. `ActiveTime` owns monotonic in-run measurements, short transactional progress checkpoints and explicitly unknown crash tails; Runtime, Nexus and the child-process poller share that one meter per invocation. The desktop edits task limits separately from connection defaults and displays effective values and uncertainty. [CONTRACTS Q3](CONTRACTS.md#existing-task-settings-and-active-time-accounting) defines the policy and limits. No new scheduler, framework or conversion recipe is involved.

The task deadline follows the same settings/freeze boundary as capacity: an explicit stopped-task update governs future requests, while an old request keeps its original timeout. Nexus owns actual receive observations and the local total deadline; the HTTP client retains separate connection/read/write/pool timeout categories. Observed status, body progress and a termination cause are attempt facts, not proof of provider completion or successful context organization. This extends the existing shared request service without another retry owner, recovery state machine or evidence-selection policy. The default remains unchanged; any live deadline experiment needs its own authorization.

Compaction prefix selection also has a continuation responsibility. A fitting text-only summary request is not a reason to consume every batch it can hold. After finding useful older history, the planner prefers a measured normal continuation that retains the newest complete batch when its actual evidence benefits from retention. Pure context-control receipts do not create this requirement. Planning includes known handoff framing/content rather than assuming an absent summary costs nothing. Its frozen target is checked again with the actual replacement handoff and relevant policy/outcome; acceptance cannot silently introduce evidence deferrals to satisfy that target. Genuinely oversized suffixes retain the existing rolling-compaction path. This is transient request planning, not a new policy store, automatic pinning or permanent retention rule. Current-request pixel absence is labeled separately from historical exposure and model understanding.

## Content and context are separate

Precise saved-document navigation is owned by the document/evidence core. The immutable version envelope stays the read identity; its optional index supplies pointers into `content` and exact sizes without copying block bodies. Evidence reads distinguish complete roots, complete pointer targets and complete requested selections. That distinction prevents a fulfilled one-block read from claiming a complete document or a complete twelve-block target from appearing truncated.

`working_context.py` describes the normal assembler's actual projection rather than maintaining a second retention policy. It adds a compact, self-costed summary and exposes optional `inspect_context` inventory/agent-selected previews. Runtime snapshots the compact input basis only when creating a new frozen normal request; replay preserves that basis. The inspector uses the recorded payload as observation authority and requires exact reconstruction before hypothetical projection. Current-batch results are explicitly outside that snapshot. It never modifies policy, head, candidate disposition or consumption. Large originals remain in the existing immutable store; no hydrated bodies are added to graph state.

PDF geometry and image derivation belong to the evidence core. The public region frame matches extraction's unrotated page points; the renderer alone converts to display coordinates and records the actual raster transform. Image extraction retains encoded image/mask streams separately from a display asset, including original/derivative identity and color/encoding provenance. The document core follows only the selected assets' original-stream references into an immutable version and export. This keeps originals portable without exposing JPX/encoded streams as preview images or adding a model-side conversion recipe. [The PDF contract](CONTRACTS.md#pdf-coordinates-and-image-delivery) owns exact fields and limits.

Keep complete immutable originals outside the model context. Distinguish:

1. Source PDF and derived evidence with source identity and provenance.
2. Received native messages and tool arguments, including rejected or incomplete candidates.
3. Accepted executable messages, tool-batch progress and original receipts.
4. Immutable document versions and explicit delivery versions.
5. The temporary model-input projection and compact continuation state.

Correction feedback is an immutable application result linked to the accepted response. It does not change that response's native acceptance status. Graph state holds only the current feedback references, counts and episode basis. Re-entry reconstructs the same transition from those records. Stable handoff identities and transactional event receipts prevent duplicate handoff references and correction/application events at the tested checkpoint gaps.

Model-facing projections can release or replace large content with accurate references without rewriting the original journal. Replay always uses the original executable call/receipt, never a shortened display of it. Saving data does not automatically decide its relevance or release timing.

Evidence hydration belongs in transient request assembly. Returning large hydrated messages as persistent graph-state updates can refill every checkpoint. Graph state keeps the compact policy and proposal/result references, not hydrated originals. The earlier graph-only policy simplification (EVT-0872/0878) rejected a competing policy activation subsystem. The current catalog commit/current-policy record supplies durable application truth for checkpoint-gap recovery; it is not a second coordinator or independently writable policy. If a framework hook is used, verify its actual persistence semantics for the installed version.

Pin selection and admission use that boundary without a per-call capacity promise. Capture validates explicit index/image/full/raw selections and saves original arguments/results. Final batch admission uses all settled native results, not guessed placeholders. A malformed context call blocks the batch's context revision and earlier pending fallback, while useful document/evidence effects remain committed. Notes replacement and selected source reuse stay explicit agent operations. Eligible releases can help a labeled transient compaction view; ineligible candidates cannot supply shortcuts to the active policy. No automatic index substitution, unpin, semantic dependency guess or extra coordination-only model request follows.

Stencil components remain inspectable evidence without a deliverable asset registration. An agent-selected page occurrence uses the existing renderer, carrying graphics-state appearance and original-stream provenance into the ordinary immutable document/export path. This preserves method choice and avoids falsely presenting decoded mask coverage as the source figure's colors.

## Authority and recovery

Immutable version files are the recommended body authority. SQLite registers their identities and commits metadata/pointers/receipts. Avoid a second independently mutable body in `blocks_json`. A staged file plus SQLite commit needs an explicit visibility/reconciliation contract. A database transaction does not also commit the external files or graph checkpoint.

Each request, accepted reply, pending batch, document version and operation receipt has one authoritative record. The graph may keep references and deterministic projections of those facts. A checkpoint timestamp proves neither committed external effects nor model exposure to those effects. Preserve local effects when replaying graph work. Do not roll back external budgets or publication with a graph branch.

Context decisions stage immutable content first. One short catalog transaction validates the task/active-policy basis, registers the settlement alias and commit marker, changes candidate eligibility, and updates the current policy only for a successful whole-policy admission. `context_disposition`, `context_commit` and `context_policy` are record kinds in the existing catalog. A staged decision object alone has no formal effect. Graph replay consumes the committed settlement's historical changes before evaluating new settings/instructions. A frozen request remains a separate prepared-input fact: it has not necessarily been sent, and neither it nor model understanding can be inferred from a checkpoint.

Outcome presentation is also a projection. The assembler inspects actual native result content: if it already carries the matching `context_outcome`, no duplicate outcome message is needed; otherwise a bounded result/reference message supplies it. Original capture receipts still say saved/not-applied. Full diagnostics remain immutable and readable. A disposition survives a blocked delivery path; active necessary-cost excess, an unfit actual compaction request, no progress or exhausted budget must be reported as a concrete block rather than described as successful continuation.

First-version recovery assumes one active writer per task. Multiple independent task workspaces may exist. Do not confuse directory isolation with model-context isolation or an OS sandbox. General multi-writer/fork/merge coordination is not a first-version prerequisite.

## Provider portability

Nexus is the intended configurable access layer, including the user's subscription route. Provider-native compaction, response retrieval and remote cancellation may be optional future route capabilities, but the baseline must work without them. Compatibility must cover actual native messages, tool-call IDs/pairs, reasoning items, streaming completion and image content, not only a `base_url` setting.

Do not force every native interaction into a lossy common message shape. Keep a native journal and an explicit, validated projection/adapter where framework messages are needed. Normal inference and history compaction share the same request service, persistent limits and cancellation gate. Framework/SDK/proxy retries must not multiply independently.

## Framework tradeoff retained

Pi offers a lightweight extensible loop and compaction/context hooks, but moving the controller toward TypeScript and integrating the Python source/document core has real coordination costs. LangChain `create_agent` offers a maintained loop and middleware but still needs domain storage/protocol contracts. Deep Agents supplies useful offloading/filesystem/summary mechanisms with stronger built-in assumptions. LangMem supplies memory/summary mechanisms rather than the complete document runtime. OpenAI Agents SDK, Claude Agent SDK and other runtimes require provider/authentication/product-fit checks. SDK maturity alone does not prove Nexus subscription compatibility.

The preferred small StateGraph keeps the Python core and native Nexus service explicit while reusing graph persistence/control primitives. This is a fit judgment, not a benchmark proving lower cost, fewer edits or greater reliability. No new framework bake-off is queued by this choice.

## Implementation boundary

No backward compatibility or old-run migration is required. Useful old code can be reviewed for selective reuse, with the original repository preserved. Dependency versions, exact API/schema names and desktop packaging details are not silently copied from an old environment. Network transport expansion remains deferred. CONTRACTS retains the discussed execution boundaries necessary for context and durable work.

The engine prints a bounded startup announcement and serves only an ephemeral loopback port with a random per-launch bearer token. Electron's renderer has no Node or generic filesystem/network IPC access. Its main process holds the credential and sends it only to the local engine for the configured model request. Important results survive in storage rather than relying on UI event delivery. Closing the app terminates the local child; reopening reads saved state and requires an explicit continuation.

Saved-output previews record the actual scroll position and CSS viewport/document dimensions, the display scale and actual PNG dimensions, as well as the requested viewport. This distinguishes a clamped scroll/window request from the pixels that were captured. The screenshot covers that viewport; it is not a claim to have reviewed the complete document.

`uv.lock` and `pnpm-lock.yaml` record full dependency resolutions. The selected main versions are Python 3.12, LangGraph 1.2.16, SQLite checkpointer 3.1.2, HTTPX 0.28.1, Pydantic 2.14.1, PyMuPDF 2.0, FastAPI 0.161.1, Electron 45.0.0, React 19.3.1, TypeScript 7.0.2, electron-vite 6.0.0 and Tesseract.js 7.0.0. PyInstaller 6.22.3 bundles the engine. These pins are implementation choices, not inherited old-environment requirements.
