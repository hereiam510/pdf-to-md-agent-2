## Context coordination policy and responsibility choices

The user selected whole-batch admission, no automatic partial context application, explicit agent reselection of uncommitted intent after new instructions, and B for confirmed necessary-content excess; [DECISIONS](#context-coordination-design-recording-boundary) records adoption. The [target design](../design/CONTEXT_UPDATE_COORDINATION.md) integrates these policies, request/decision responsibilities and planned acceptance. It is now implemented; CURRENT_STATE owns the local checks and remaining real-model limits. This options record does not authorize another increment.

The former immediate/deferred route remains a meaningful unselected alternative, particularly for early commitment before cancellation. It could defer intermediate X+Y and compose release X; this alone does not provide the selected whole-revision promise when earlier changes already fit. Neither moving admission nor extracting a helper fixes the three retained estimation/projection controls automatically. The user rejected automatic partial application for this target; a generic rule to borrow every shorter pending pin/note remains unselected. Whole-old-policy snapshot import and a user keep-pending switch are not required by explicit agent content reuse. The former C recommendation would retain automatic eligibility for an already feasible candidate after a settings reduction when the active diagnostic route was blocked. That is a coherent alternative tradeoff, not an established logical contradiction, but it is not the selected policy. B favors a durable disposition independent of notification availability; restoration after that disposition requires explicit agent reselection. Unknown estimates and pure history pressure retain their separate treatment. ## History-pressure admission: retained option and adoption basis

The following preserves the original option comparison and its 2026-10-25 adoption notice. Its prospective wording and reconsideration conditions describe that earlier evaluation, not a pending feature. D15/D18/D20 subsequently refine whole-batch eligibility and policy B; [the current contract](../design/CONTEXT_MANAGEMENT.md#q2-context-transitions) and [the adopted integrated design](../design/CONTEXT_UPDATE_COORDINATION.md) govern present behavior. The human selection is recorded in [the original decision](REBUILD.md#consequential-alternatives-and-corrections).

**Disposition:** Adopted for the 2026-10-25 history-pressure coordination increment after dual-protocol local reproductions. Exact behavior is owned by [Q2](../design/CONTEXT_MANAGEMENT.md#q2-context-transitions), the decision by [DECISIONS](../decisions/REBUILD.md#consequential-alternatives-and-corrections), and implementation/checks by [CURRENT_STATE](../CURRENT_STATE.md). This adoption includes notes and release updates, not only pins. Other options on this page remain unselected.

If a proposed pin could fit after removable history is compacted, the agent could retain the proposal, compact appropriate history, and reassess it against the resulting input. If required instructions plus the selected pins and request overhead already exceed capacity, compacting unrelated history cannot solve the problem. The actual compaction envelope must also fit; a hypothetical small final context does not prove a feasible compaction path.

**Potential value and tradeoff:** A useful pin might become admissible without changing its representation. Compaction adds work and can lose useful semantic detail despite preserving raw history. Coordination must also avoid repeatedly retrying an infeasible proposal or applying a blocked policy before a usable next input exists. Existing atomic rejection and working-policy preservation should remain intact.

**Revisit when:** A concrete task or proportionate local analysis shows rejection caused by reducible history, a feasible compaction path, and a useful evidence selection that existing agent-controlled choices handle awkwardly. Do not infer this need from a raw pin that cannot fit even with minimal history.

**Proportionate evaluation:** Use fitting-after-compaction and irreducibly-oversized controls. Check that the former can progress, the latter receives actionable feedback, and both preserve originals, prior policy on rejection, consumed usage and frozen-request boundaries. Inspect retained instructions and dependencies as well as source-led saved/reopened/exported output. Selected coordination may invoke existing bounded compaction under the active policy; it does not select automatic release, lower fidelity or a narrower conversion scope.
