## Reference interpretation and destination policy

### Whole-document analysis

Use the existing whole-document CommonMark/table/footnote rendering pipeline. Analyze effective `img.src` and `a.href` destinations, including supported raw HTML and reference-style links whose definitions are in other blocks. Do not scan individual blocks independently or use a Markdown-text regular expression as the reference authority. Code spans, fenced examples, HTML comments and unresolved reference syntax that remains literal text are not asset references.

The analysis must agree with the safe renderer on tag/attribute interpretation and HTML entities. Before discarding information through sanitization, reject duplicate `src` attributes on an image or duplicate `href` attributes on an anchor as unsupported resource markup; retain the original candidate. This applies even when the duplicates currently contain equal values, so the rule is deterministic. Other markup that would make reference collection and the supported rendered destination disagree must be rejected with useful feedback rather than guessed. Do not broaden this into general source-HTML repair. Image restrictions cannot be bypassed by having sanitization erase an otherwise unsupported image destination.

Build one deduplicated set of asset paths from the complete merged document, retaining whether each occurrence is an image or hyperlink for diagnostics. Saving, saved-version assessment and transient preview binding must use the same reference interpretation. A data URL created by the app for display is an output of binding, not a new source reference that should be scanned back into the document.

### Supported destinations

Here, a **canonical asset path** is the exact tool-returned relative path `assets/<64 lowercase hexadecimal SHA-256 characters>.<lowercase extension>`, with no leading slash/dot segment, percent escape, backslash, query or fragment. The path must match a registered display-image asset in the current task; a matching path shape or an asset owned only by another task is insufficient. The extension and bytes must correspond to that registered asset. This selects no new image format and no generic attachment capability.

The table describes parsed attribute destinations, not a rewrite of original Markdown. HTML entity decoding performed by the supported parser can produce a canonical destination while the original spelling remains saved unchanged.

| Input condition | New-save behavior |
| --- | --- |
| Canonical destination in an image embed or hyperlink, registered to this task | Validate the asset and associated originals, then include them. The same path used repeatedly or in both forms produces one file entry. |
| Canonical destination absent from this task, including a foreign-task-only asset | Reject with the destination and task-local registration requirement. Do not search or copy another task's files. |
| A local reserved-asset variant, such as `./assets/...`, `../assets/...`, `/assets/...`, encoded spelling, different case, backslash, query or fragment | Reject as noncanonical with guidance to use the exact returned `asset_path`. Do not normalize it into an accepted path or silently ignore it. |
| An image destination that is not a supported canonical task asset | Reject under the existing local-image restriction, including remote/file/data image inputs. Sanitization is not a substitute for this validation. |
| Ordinary external hyperlink, fragment-only anchor/footnote, or unrelated relative source citation | Preserve existing Markdown and sanitization behavior; do not fetch it or include files. This batch does not validate arbitrary citation availability. |
| Asset-looking text in a code example, comment or literal unresolved reference | Preserve it as text; no asset lookup, rejection or inclusion on that basis. |

For detecting a **reserved-asset variant**, inspect a URL's local path without accessing the filesystem: exclude fragment-only links and URLs with a scheme or authority, separate query/fragment, percent-decode once for classification only, split both slash spellings, and treat a case-insensitive `assets` path component as reserved. This deliberately catches parent/root/nested/encoded spellings without resolving them against a directory. Only the original parsed destination's exact canonical form can be accepted. An external URL whose remote path contains `/assets/` remains external. This bounded classifier is not a general URL canonicalizer, host-file resolver or promise to repair every arbitrary relative hyperlink.

Do not silently convert links to embeds, remove promised links, accept a partial save with an unresolved required asset, include every task image, or infer a replacement image. Reference errors use the existing rejected-edit/candidate mechanism; the error identifies the destination/attribute and the reason, with an actionable correction. It must not expose another task's contents. A model can reuse its retained candidate in a new valid edit under the existing rules.

## Save and immutable dependency preparation

The save flow is:

1. Preserve the received candidate through the existing Dispatcher boundary. Resolve the explicit task/base and apply the requested operations/page changes to the working document.
2. Validate the merged document and analyze its complete Markdown. Apply the reference policy above to both hyperlink and image occurrences.
3. Resolve the union only through this task's registered display assets. Verify selected bytes and the associated image/mask original references through the existing immutable storage rules. Prepare the existing `assets`, `originals` and file/manifest records; do not add another mutable body or attachment registry.
4. Prepare the immutable version files, then use the existing conditional SQLite registration/head/receipt transaction. A reference failure cannot publish a version or advance head. Later file/transaction failure retains useful unregistered work without publishing it.
5. Return the existing operation result. Replay returns the historical receipt/version without changing a newer head; it does not re-run dependency discovery against a new document or fill old omissions.

The same policy applies to partial and complete content claims, ordinary edits, rebuilds and candidate reuse. A partial claim permits unfinished content; it does not make a deliberately referenced missing image file valid. Metadata-only edits still validate all references in the merged result. Removing the final reference removes that asset and any originals no longer needed from the new version only. Source PDF, old versions, original candidates and task evidence remain preserved.

Display bytes, associated originals and provenance follow the [existing image contract](../../design/PDF_EVIDENCE.md#pdf-coordinates-and-image-delivery). The source PDF is not newly copied into delivery. No extraction, resampling, color conversion, OCR or provider work is performed by reference resolution.

## Saved-version assessment and diagnostics

Saved-version byte integrity and asset-reference completeness are separate checks. Preserve the current integrity gate: a registered version file that is missing or has a different hash is an integrity failure, not a harmless warning. Do not publish a verified ZIP from corrupted registered bytes.

For an integrity-valid version, assess its recorded content against **that version's** asset/original/file inventories. Do not satisfy a missing dependency from task blobs, another version, the current head, a source render or a remote location. An older version can be byte-consistent yet have an incomplete inventory, as in A03.

Add an out-of-band `asset_reference_check` to the selected-version API response and the host export response. It is derived response metadata; it is not written into immutable `document.json`, Markdown, HTML, manifests, historical operation receipts or existing persisted export receipts. Required semantics are:

| Field | Meaning |
| --- | --- |
| `status` | `ok` when all supported local asset references and associated declared dependencies are accounted for; `incomplete` when analysis identifies a missing/invalid reference or inventory relationship; `unavailable` when analysis cannot finish. `ok` is not a source-fidelity or all-links certification. |
| `issues` | A list identifying the affected destination and image/hyperlink role where available, a stable reason and readable explanation. Representative reasons distinguish noncanonical destination, missing version asset, missing associated original and unsupported resource markup. Do not invent an exact block/offset locator for a cross-block reference. |

Responses already bind the check to their task/version identity; consumers must not combine it with another selection. Empty `issues` with `ok` is normal for an accepted repaired save. If analysis is unavailable, say so instead of returning a false pass. A later exported response can reassess with the same interpretation without altering the stored original receipt. Existing `verified` continues to mean actual ZIP membership/byte consistency only.

For integrity-valid historical incomplete versions, preserve inspection and exact original export. Show the missing-asset diagnosis beside the saved result and in export feedback; identify the original complete/partial field as an agent claim rather than using it to override the diagnosis. Do not add diagnosis files, missing images or new links to the original ZIP. Correction, if later requested, creates a new version through ordinary editing. Original A03 data is not a repair fixture to mutate.

## Preview binding and return behavior

Create the transient app preview only after loading and verifying the explicitly selected version. Resolve supported references from the immutable version's verified files and inventory. Do not require a separate task-blob read to supply a file already preserved in that version, and never substitute a newer version's image.

Reuse the demonstrated data-URL approach for supported display-image bytes, applying it to both `src` and local `href` attributes through parsed-attribute rewriting after source sanitization. Choose MIME from the validated registered image type. Do not add arbitrary source-provided data/file URLs to allowed link schemes or use global textual replacements. Portable saved Markdown/HTML keeps its original relative paths; data URLs belong only to the derived app view. The iframe keeps `sandbox=""`; no source scripts, same-origin permission, new windows, downloads or external-resource fetches are enabled for this repair.

Following a bound image link displays the selected image in the existing sandboxed preview frame. Add an app-owned **Return to document** control outside that frame. It is available whenever a matching saved preview is ready, even if the frame has not navigated. It recreates the preview from the already-loaded matching snapshot; it does not consult head, invoke inference, save content or require access to the sandbox's DOM. A simple frame remount/revision is sufficient; no navigation broker or general URL handler is required.

Bind preview-reset state to `(job, version)`. A task/version switch, failed/pending load or entry into the editor invalidates the old preview/reset action. Preserve the existing explicit-selection and default-follow-head semantics: an explicitly selected old version stays selected when head advances; if the existing default-follow mode actually selects a new head, discard the prior image-view context and load the new matching view. A return action never silently applies an old snapshot to a newly selected task/version. Export always uses the matching loaded version, including while the frame displays an image. Unsaved editor content remains governed by the existing editing contract.

If a historical link has no valid dependency in the selected version, keep its label in the transient preview but remove its navigable target and show the diagnosis outside the sandbox. For a missing image dependency, preserve available alternative text and indicate unavailability; do not fabricate a substitute image. Preserve full raw Markdown access. When assessment itself is unavailable, do not bind unverified resources or describe them as usable; retain an honest unavailable diagnostic.

Data-URL construction must preserve complete original bytes. Inspect representative larger/repeated-image behavior during implementation, but introduce no arbitrary image-count/size quota, hidden truncation or automatic resolution reduction. A supported failure of this mechanism in the actual desktop would require revisiting that mechanism with evidence, not weakening isolation or presentation fidelity.
