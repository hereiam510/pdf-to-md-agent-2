:codex-annotation{index="1"} 好，確定採用**混合方式**：

- **平時由 agent 自主管理**：選擇讀取、保留、釋放或重新取回證據，也可主動整理歷史。
- **接近容量限制時由 app 觸發整理**：預留足夠空間，讓整理本身能完成。
- **保留內容由 agent 判斷**：app 負責實際組合 context、維持訊息結構及保存完整原始記錄。

接下來要定的是**整理的優先次序與保護範圍**。我建議：

1. **先考慮釋放可精確取回、目前不再需要的證據**，例如已完成部分的大量 OCR 或圖片結果。
2. **仍不足時再整理較舊的工作歷史**，保留必要近期內容及繼續工作的狀態。
3. **持續有效的使用者要求、未解依賴和未保存的有用成果必須保護**；未保存內容可以先完整存入工作檔，context 保留精確引用。

這是優先考慮的順序，agent 可以按當前任務選擇直接摘要或保留證據。全文與原圖仍可取回，摘要也不能代替完整來源或完成範圍的記錄。
