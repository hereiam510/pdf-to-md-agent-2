對，你的方向正確。**Context management 應分成「對話／工作歷史的壓縮」與「檔案證據的讀取、保留和再取回」兩部分**，兩者要協調設計。

:codex-annotation{index="1"} 按你的要求，方案一律以 **不依賴 provider 原生 compaction、background retrieval 或遠端 cancellation** 為前提，讓不同訂閱連線或模型共用同一套基本機制。

你所說的「model’s ordinary context compact」，我會精確定義為：**由 app 請模型整理工作狀態，再由 app 重建下一次請求的 context**。模型寫出摘要本身，不會自動減少後續送出的歷史。

兩部分的分工可以是：

| 部分 | 要解決的問題 | 建議方式 |
|---|---|---|
| **對話／工作歷史壓縮** | 長任務累積了大量討論、工具呼叫、舊草稿，持續佔用 context | 保留原始要求、有效決定、未完成事項及必要近期內容；將較舊歷史整理成可繼續工作的狀態 |
| **檔案證據管理** | 一次讀入太多資料，或已處理的文字、OCR、圖片一直留在 context | 按工作需要讀取；保留當前相關證據；其他資料可退出 active context，之後從完整原始記錄精確取回 |

還需要一個共同基礎：**可靠的工作狀態與來源索引**。這不是第三套壓縮，而是確保壓縮後仍知道「做了甚麼、還欠甚麼、證據在哪裡」。

例如，保存成功的版本 ID 應由 app 提供；跨頁表格還未接完、某個字仍有疑問，則由 agent 記錄。不能只靠一段自由摘要混在一起。

我建議按以下方式討論方案。

**1. 先定義每次請求應帶甚麼**

可以分成四類：

- **持續有效的要求**：使用者目標、來源、範圍、格式和明確限制。
- **目前工作狀態**：已保存版本、進行中的內容、未解問題、跨頁關係和下一步。
- **近期工作內容**：目前仍需要的對話、完整工具呼叫／結果，以及尚未保存的有用內容。
- **當前來源證據**：正在處理或核對的文字、版面、圖片等。

完整歷史與原始資料另行保存。**存於磁碟的資料仍然可取回，但不能假設模型已經知道其中的內容。**

**2. 檔案管理要同時處理「進入」與「退出」context**

這點很重要：只在讀完後 compact，仍可能被一次巨大的工具回覆塞爆。

因此需要兼顧：

- **讀取前**：讓 agent 知道資料位置、範圍、結構和大小，能選擇全文、頁面、欄位、區域或原圖。
- **讀取後**：agent 判斷哪些證據仍與目前工作相關，哪些可以釋放；保留精確取回的位置及必要的未解關係。
- **重新取回**：能直接讀回原文、指定欄位或真正的圖片像素，避免只能取回摘要。

這不代表固定只讀文字或固定幾個欄位。跨欄閱讀、表格、字體強調或圖片標籤，需要的資料不同。全文和原始資料仍應可直接取得；單次無法容納時，要明確呈現限制及可用的分段讀法，不能默默截斷。

**3. 對話壓縮要保留「繼續工作所需的狀態」**

摘要至少需要涵蓋：

- 使用者要求及後續修正。
- 已完成、已保存與尚未保存的工作。
- 未完成範圍、疑問和跨頁依賴。
- 重要判斷及其來源位置。
- 接下來要做甚麼，以及應到哪裡取回資料。

尤其要保護**已寫好但未成功保存的內容**。只留下「正在處理第 12 頁」會迫使模型重新閱讀、重新生成，可能增加成本及差異。

壓縮應發生在完整工具結果已收到、工作狀態一致的邊界。舊歷史保留，摘要失敗時也不能先把原 context 丟掉。

**4. 觸發方式是這次最需要決定的設計選項**

我的建議是 **app 提供容量資訊與預警，agent 選擇適合的整理時機**：

- App 按所選模型／路由的可用限制，估算下一次完整請求的大小，預留輸出及管理所需空間。
- Agent 可在完成一個工作單元、證據不再相關時，主動釋放或整理。
- 接近容量限制時，app 明確提示需要處理 context；具體壓縮哪些內容仍由 agent 判斷。
- 若已無法送出，要保留工作並明確處理超限，避免把相同過大請求當網路錯誤反覆重試。

不能等到 context 完全塞滿才要求模型摘要，因為**摘要請求本身也需要放得進去**。另一方面，不同模型的文字、圖片計量及路由上限可能不同，不宜先指定一個通用的「到 80% 就壓縮」規則；估算的不確定性也要保留。

這是建議中的新政策，尚未決定採用或更改預設。

目前已有的 `read_evidence`、選擇性讀取、`manage_evidence` 和 `checkpoint`，分別提供了精確取回、證據釋放及新 context 延續的基礎。現有缺口主要是：**容量感知、過大回覆的處理，以及何時採取哪種管理動作的協調策略**。選擇性管理目前也不能縮減所有舊草稿和操作歷史。[現有 context 設計](C:/Users/laichungling/Documents/ChatGPT/pdf-to-md-agent/docs/ARCHITECTURE.md:56)
