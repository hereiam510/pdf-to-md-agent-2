## Meaningful alternatives and tradeoffs

| Candidate | Useful outcome | Costs and limits that affect selection |
| --- | --- | --- |
| Existing UI, saved-acceptance diagnosis and precise evidence reads | Inspect the first controlled continuation using available evidence. | Low new engineering cost; manual correlation remains. Existing availability does not prove sufficient ease of use. |
| On-demand local timeline/inspector or JSON/HTML export | Answer one task's lifecycle questions with exact evidence links, pagination and explicit unknowns. | A useful bounded feature, but joins, rendering, consistency and upkeep still cost work. Avoid building a general dashboard before proving the need. Small bounded status/cursor fields may still fit ordinary polling. |
| Historical out-of-band Langfuse/OTLP projection | Reuse saved domain facts in an external query/comparison interface without an SDK on the conversion path. | Does not invent missing timings or live progress. Requires coherent reads, replay/deduplication policy, data permissions and backend compatibility. Concurrent readers still use CPU/I/O and may affect WAL lifetime. |
| Online custom observations, optionally with scoped LangGraph callbacks | Measure future phase duration and expose execution structure while the app runs. | Requires content controls, lifecycle management and measured failure/overhead isolation. Callbacks alone do not observe custom HTTPX/Dispatcher internals; mixing appropriately scoped layers is possible. |
| General OTel tracing plus targeted profiling | Attribute CPU, serialization, SQLite, verification or PDF-processing costs where that is the question. | Trace viewers do not supply PDF semantics. Profiling and end-to-end elapsed measurements answer different questions. |
| LangGraph/LangSmith framework tracing | Observe graph invocations/nodes through supported framework hooks. | An alternative interface, not automatic coverage of Nexus native acceptance, durable receipts or domain recovery. No switch of backend or framework is selected. |

Historical projection is well suited to preserved domain facts; online observations are needed for timings that were never recorded. A hybrid can correlate both while labeling provenance. A local projector has no automatic claim to zero semantic loss: incorrect ownership, time origins, state joins or inferred defaults can misrepresent the same facts as an online adapter.

### Why the catalog is not already an export queue

[Store.put_tx](../../src/pdfmd/storage.py) changes `data` on conflict but preserves `created`; there is no general record `updated` column. An event-sequence cursor therefore misses mutable record transitions unless they have a corresponding event. Events are not a complete atomic mutation log: [Documents.edit](../../src/pdfmd/documents.py) commits version/head/operation before separately writing `version_saved`. A process exit between those actions can leave a committed version without that event.

An exporter may use a complete on-demand projection, explicit state reconciliation/deduplication, or a separately justified change sequence. Neither a new durable spool nor schema changes are automatically necessary. The selected method must account for updated records, commit/event gaps, interrupted exports, duplicates and backend update behavior. A hash identifies content; it does not prove causal ownership or snapshot consistency. Missing historical times remain missing. Source durability guarantees are not strengthened by calling the catalog an exporter queue.

## Candidate observation responsibilities

These are design considerations for a selected increment, not new executable schemas or acceptance gates.

Every candidate preserves agent choice of tools, methods and reconstruction scope; full/raw/field/range/native-pixel source access; useful candidates and drafts; original receipts; legitimate instructions and pins; frozen boundaries; and all consumed or unknown records. Efficiency must not come from hidden truncation, reduced fidelity/scope or a compulsory tool order. Tools execute only after complete reply validation, with additional handoff validation for compaction; partial replies and cross-request assembled arguments are not executable batches. Trusted scripts remain off by default and, when enabled, run with host-user permissions rather than an OS sandbox. The existing contracts own these rules; observability adds no execution authority.

| Boundary | Candidate observation and identity | Meaning that must survive projection |
| --- | --- | --- |
| Invocation/run segment | One execution interval linked to a stable task identity and source/app revision. | Reopen creates a new segment; do not turn downtime into measured active work or pretend one live span survived the process. Task/session grouping is separate from causal lineage. |
| Preparation | Kind, preparation/capacity decision, estimator identity and safe frozen-input reference. | A frozen request with no attempts is prepared, not dispatched. Current cumulative limits and frozen route/wait/payload have different authority. |
| Actual attempt | Request plus actual attempt ID, native protocol, receive summary, usage provenance and outcome. | HTTP success, terminal protocol completion and native acceptance are separate. Retrying an export is not a new model attempt. |
| Acceptance and context | Staging/publication markers, handoff application or rejection, repair and disposition refs. | Saved acceptance evidence, catalog publication and graph projection are separate; native acceptance does not establish a valid handoff. |
| Tool/effect | Logical operation plus fresh-execution/reuse/skip classification and resulting candidate/version refs. | Reconcile returns an existing receipt; unstarted skips are not failed executions. A committed effect may predate a graph checkpoint or its event. |
| Recovery and delivery | Exact resolution/continuation lineage, selected immutable version and export facts. | Resolution is not retroactive acceptance; a saved/exported version is not source-led content acceptance. |

Stable domain keys should remain available alongside backend trace/span IDs. Re-export/reopen must not double-count generations or committed effects. A task can group multiple execution-segment traces; a single long task trace remains an alternative only with justified lifecycle/backend semantics. `session_id=job_id` provides grouping, not lineage, deduplication or correctness. Readable local refs are not automatically accessible to an external backend.

Callback node success means that node returned; it must not be promoted to accepted content or committed effects. A node may truthfully execute while its children reuse receipts. Custom observations can cover the native boundaries and scoped callbacks can add graph structure without duplicating the same generation. Automatic input/output capture must be assessed against the chosen data policy. No mandatory framework layer, callback ban or runtime replacement follows.

### Time and streaming semantics

Use wall timestamps for placement and monotonic measurements for duration within one invocation, recording the origin and whether a fact was observed, reconstructed or unknown. `attempt.started` precedes the receive clock's origin; adding a receive offset to it does not produce an exact wall timestamp. Parent/child spans overlap, so their durations are not additive task time. Receive elapsed includes client work and is not pure provider compute. Existing `ActiveTime` remains budget authority; a trace cannot repair unknown crash tails or rewrite recorded consumption.

In `Nexus.exchange`, `moment = elapsed()` is sampled for the yielded HTTPX body chunk **before** `record_chunk`, `decoder.feed` and `record_observation`. The same moment supplies that chunk's body/event/progress/terminal milestones even though classification and persistence happen later. The timestamp excludes its own chunk's persistence/decoding duration; earlier chunks' synchronous work and buffering can affect later observations. It is not a raw socket arrival or upstream first-token timestamp. Separate timers are needed to attribute persistence, decode and observation costs. Also distinguish transport bytes, effective generation progress and protocol terminal state; heartbeat traffic does not become model progress.

F03 timing cannot be a small change to `Dispatcher.settle` alone. `Documents.edit` commits its operation with the version/head and the dispatcher returns early; reconcile, skip, recovery and interrupted started operations also have distinct lifecycles. A logical operation duration, one fresh execution duration, receipt-reuse cost and an unknown interrupted tail are different fields/observations. Preparation timing should distinguish fresh assembly from frozen-request reuse without modifying the frozen input.

Prefer attempt-level counts and summaries over exported observations for every chunk. Existing durable raw chunks remain unchanged. Candidate additional measures include aggregate persistence/decode time and maximum observed inter-progress gap, with explicit definitions and measured overhead. Standard OTel batching exports finished spans; events attached to an unfinished long span do not by themselves guarantee live remote visibility. Keep local receive progress useful while offline. If remote live stall diagnosis is selected, verify a bounded low-frequency progress mechanism and backend visibility rather than assuming a final generation span suffices.

### Usage and outcome semantics

Keep local BPE proxy/reserves, native reported usage, derived category mappings, conditional price estimates and actual billed/subscription fees separate. Cache/reasoning categories are subsets only where native semantics establish that; do not sum overlapping categories. Missing usage is not zero. Totals should distinguish known subtotals, unknown attempts and coverage, including useful raw usage from a complete native reply rejected before acceptance. Such extraction is diagnostic provenance, not permission to overwrite original attempt usage.

`Runtime.compact` calls `Nexus.send` and settles native acceptance/usage before `apply_handoff`. A later `HandoffRejected` preserves that settled usage and should be presented as native accepted / handoff rejected. This differs from native parsing rejection. R07's uncaught container-type failures require their separate correction; observability cannot relabel them as ordinary caught rejections.

Langfuse can infer usage/cost using model definitions. A Nexus model alias must not silently acquire a direct-provider price sheet or fill unknown usage with inferred certainty. A selected adapter must verify its inference/display behavior and preserve incomplete totals. No current trace can reveal gateway internal retries, prove remote cancellation, recover unreturned costs, expose hidden reasoning, or certify source fidelity.

### Optional operation, queue and failure isolation

Candidate modes are disabled, local diagnostics, explicitly enabled external metadata, and separately selected richer content capture. Disabled/offline telemetry must not block conversion or recovery. For online export, prefer a bounded queue, observable drops, finite exporter timeouts/retries and a bounded shutdown flush outside effect/catalog transactions and per-chunk work. Do not wait for export before accepting replies, executing tools or honoring Stop. A hard process exit can lose telemetry; it must not lose or reinterpret authoritative local facts. Current Electron shutdown kills the engine child, so SDK finalization is not a guaranteed delivery mechanism.

Telemetry retry must never initiate model/tool retry or change request/attempt/job acceptance. Asynchronous export still has serialization, CPU, memory and contention costs. An out-of-band process also consumes resources. Compare these costs in the intended workload rather than claiming zero overhead or using old R02 elapsed times as a current threshold. Reconstruct only the domain facts the local evidence supports; do not silently fill missing transient measurements.

## Data, deployment and unresolved choices

No content tier is adopted. A candidate initial external projection uses explicit field allowlists: opaque identities, operation names, structured status categories, sizes/counts, timing, estimator/version and proven usage fields. Filenames, absolute paths, endpoints, free-text errors, prompts/replies, tool arguments, page text and images may contain private data. Metadata is not inherently safe; logical refs such as `candidate:<operation>` are not SHA-256 digests, and content hashes can still enable linkage. Scope identity and safe detail at construction time rather than relying only on redaction after capture.

Metadata can show repeated reads/compactions without versions. It usually cannot explain a mistranscribed negation, a wrong table relationship, or an inaccurate handoff. Those questions need selected source/content evidence, which may be inspected locally or included under a later explicit transmission decision. Full content is neither automatically authorized nor permanently banned from Cloud by this discussion.

Cloud reduces infrastructure operations but adds a chosen external-data boundary. Self-hosting provides deployment control with real Web/Worker, Postgres, ClickHouse, Redis/Valkey and object-storage operations; it is not merely an SDK installation or proof of adequate security. No account, service, paid tier, region or hosting policy has been selected. Remote diagnostic retention and local source/recovery preservation are independent. A Cloud data-access window is not a deletion deadline; verify plan-specific retention, media/dataset behavior and deletion before relying on it.

Current Python masking guidance distinguishes export-stage `mask_otel_spans` from legacy synchronous `mask`. The former runs after Langfuse media handling and affects that client's exported span copy, not every exporter. Exclude unauthorized data before instrumentation/media handling; a final masking hook is not a universal disclosure boundary. A collector outside the approved boundary is already an external transmission.

Near-term choices depend on the next outcome: inspect existing domain facts locally, evaluate a Langfuse query/UI workflow with synthetic data, or measure live phase timings in isolated local execution. Only the UI/export option needs a destination decision now. Private content capture, production retention and long-term deployment can remain open until their dependent work is selected. Do not turn these into a large mandatory questionnaire.

## Official guidance consulted and remaining design boundary

- [Langfuse observability](https://langfuse.com/docs/observability/overview) and [instrumentation](https://langfuse.com/docs/observability/sdk/instrumentation): custom observations and integrations can coexist; automatic IO capture has cost and data implications.
