6. **Model-controlled resource use is uncapped.** `render_page` allows 1200 DPI on a full page, which is over 100 megapixels, with no pixel limit. A `MemoryError` isn't in the dispatcher's caught exceptions, so it ends the whole run as `internal_error`. There are also no caps on received stream bytes, SSE line length, or PDF size at import.
7. **Parse-error gap.** `parse_reply` is wrapped in `except (ValueError, KeyError, TypeError)`, so an `AttributeError` or `IndexError` from an oddly shaped reply escapes `send()` and leaves the request marked `in_flight`.
8. **Export fails on some filesystems.** `os.link` for exclusive publish doesn't work on FAT/exFAT, some SMB shares and some sync folders. It also leaves a `.tmp` file next to the destination when it fails. Falling back to `open(..., "xb")` and adding a `finally` cleanup would fix both.
9. **Environment leaks.** `run_script` filters by name substring, so `AWS_ACCESS_KEY_ID` passes, and `ocr()` and `preview()` pass the full environment, including `PDFMD_LOCAL_TOKEN`, to a network-capable Node process. An allowlist is safer. Also, `terminate()` doesn't kill grandchildren.
10. **Remembered credential.** Windows encryption protects the key from other users and machines, but not from same-user code, so an enabled script can decrypt it. This is worth stating in the README.
11. **Scaling.** `Documents.version()` re-hashes every file in a version, including all images and original streams, on each call. Each tool call re-reads and re-verifies the whole source PDF. `objects/` has no garbage collection.
12. **Untrusted PDFs are parsed by MuPDF inside the engine process,** which also holds the API key in memory. A worker subprocess would isolate that.
