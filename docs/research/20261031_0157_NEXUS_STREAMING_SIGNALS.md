## App implementation guidance and verification boundary

The implementation uses the existing HTTPX 0.28.1 dependency. Its [timeout guide](https://www.python-httpx.org/advanced/timeouts/) distinguishes connect/read/write/pool waits; read timeout concerns receiving a chunk, not semantic generation progress. Its [async guide](https://www.python-httpx.org/async/#streaming-responses) documents streamed decoded bytes, manual `send(..., stream=True)` and the caller's responsibility to close a manually streamed response. The app uses manual streaming so generation waiting ends at a complete protocol terminal before separately bounded response/client cleanup. It owns first-progress/idle/optional-total decisions while retaining finite connection/upload/pool waits. Disabling the HTTPX read timer in streaming mode does not disable the app's selected waiting limits, Stop or persistent task budget.

Relevant protocol definitions are [Chat Completions stream chunks](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events) and [Responses streaming events](https://developers.openai.com/api/reference/resources/responses/streaming-events). These are encoding references, not proof that a subscription gateway implements every official API feature. No new dependency, framework, provider-native compaction or background retrieval is selected.

The starting 600-second first-progress allowance and 300-second progress-idle allowance are human-selected engineering values. Earlier successful compactions' 137-151-second total durations do not calibrate either allowance. Silence may be hidden reasoning, buffering or a stalled connection; expiry records the app's observation boundary, not a proved upstream cause or cancellation.

Local scripted tests can establish parser, timer, storage, recovery and delivery preservation. A separately authorized actual-route run is required to measure first progress and event gaps, establish current Nexus forwarding, obtain an accepted handoff and assess whether the agent resumes useful faithful editing. A stream's progress or successful termination alone does not establish fourteen-page completion or explain the earlier editing plateau.
