Local development may store the authorized key in ignored `private/api-key.txt`. The file contains only one credential; no quotes, `KEY=` prefix or extra lines. `private/provider.json` contains endpoint, protocol, configured model, `api_key_env` and runtime settings, never the key itself. Local setup may start with a candidate config and empty key template; current readiness belongs in CURRENT_STATE, and private files are not distributed through Git. Without `-PrivateDirectory`, an existing checkout-local `private/provider.json` selects that private directory; otherwise Git's primary-worktree path selects shared `private/`. Another clone/machine needs its own local setup or an explicit accessible directory. Private files and virtual environments are not copied by Git/worktrees.

The default interpreter is this checkout's `.venv/Scripts/python.exe`; set up its locked environment locally. `-PythonPath` explicitly selects another suitable project interpreter. Mutable runs, task paths and outputs belong to separate task directories in the primary checkout, not the private directory. Shared configs/credentials need not be rewritten by conversion. `-CheckOnly` reads local files but starts no agent and makes no network call. It reports paths/fixed issues without credential contents. Exit 0 means these local file checks passed, exit 2 means missing/empty local prerequisites, and exit 1 means invalid arguments/config or launcher failure. It does not validate installed dependencies, the complete app schema, key validity, endpoint connectivity or model access. It is not authorization to run a comparison. An actual launch returns the child exit code. `-AllowHostScripts` forwards the explicit opt-in; `-RemoteSettled` applies only with `-Resume` and records a caller assertion, not remote cancellation/query. --- Original lines 538-561 ---
The initial engine is Tesseract.js 6.0.1/core 6.1.2 with local chi_tra/eng best_int data. No source,
image or text is sent to a recognition service. Other languages need an intentionally installed
matching data package; a missing language returns a failed run, never silent English fallback.

```json
{"operation":"ocr","args":{"document":"<imported-id>","pages":[10,11],"languages":["chi_tra","eng"],"dpi":300,"psm":3}}
```

Regions use the same unrotated PDF points as other tools. PSM 3 is automatic layout, 6 assumes a
text block, 7 a line and 11 sparse text. OSD is not installed; use a supported recognition mode.
These are selectable tactics, not a conversion recipe. Each selected image is a new render and
fresh recognition; existing PDF text is not reused as OCR output. Installed language files are
checked before initialization. Each requested language is initialized independently, then combined;
returned language records include package version, uncompressed SHA-256/size and initialization state.
Any engine language-load diagnostic prevents a successful recognition claim.

OCR returns raw text, blocks, TSV and word candidates with confidence, render-pixel boxes and
unrotated `bbox_pdf` boxes. Low confidence (below 80) and empty recognition warn; even high confidence
does not establish accurate content or table relationships. `status` and per-page execution state
distinguish failures/timeouts. `workspaces/<document>/ocr/<run>/` retains requests, raw recognition,
logs and current/final batch status. Completed page results survive a later failure/cancellation;
scratch OCR evidence is excluded from document export. The agent composes and checks saved content.
The Node worker uses worker threads in one process; killing that process stops its recognition.
Windows bundled distribution and performance beyond the tested excerpts are not verified.

Each save copies referenced assets into an immutable version directory and generates all artifacts
from that content. File locks serialize writers; a stale `base_version` fails instead of overwriting
someone else's content. Atomic publication leaves the previous version usable on failure. Reopen
checks saved file hashes and Markdown/JSON identity. Export uses that snapshot, not mutable task assets
or a recursive shared workspace. The ZIP's `manifest.json` records file hashes and the version.
Hashes establish integrity, not content fidelity or adversarial tamper resistance.
