The small Python controller uses native HTTPX2 transport and the shared MCP registry. Actual source-to-package, image/revision and useful saved-work evidence support this working choice. Exact full URLs and separate wire encoders make provider behavior explicit. A mature SDK is eligible for a demonstrated need; one shared controller/core is the design.

Chat preserves tool pairing before linked user image messages. Responses uses native function outputs/images and replays output/reasoning with encrypted reasoning requested for stateless use. One semantic result plus distinct diagnostics/pixels reaches the model; complete raw records, exact first-call selection and lossless field/range/native-image reads support autonomous evidence access.

Full history is default. Optional explicit read-evidence projection and standalone fresh-context checkpoint are not native compaction or automatic lossless memory. New jobs support explicit finite resumption over durable native/context state, exact arguments/replies and publication reconciliation. Arbitrary historical conversations are not imported; unknown unacknowledged local effects stop. Safe diagnostics and default-off finite recovery preserve work without establishing upstream repair. Per-attempt provider evidence retains complete framed native events and structurally native HTTP-200 JSON candidates. Error bodies/frames, raw heartbeat comments and unparseable/unframed/non-native fragments are withheld with safe byte/hash/reason metadata. Complete source/tool raw evidence/native pixels remain freely accessible.

Both transports normalize into one complete validated reply/tool-batch boundary and one app retry owner. They retain the registry, complete evidence/native pixels, reasoning, context policy, continuation, publication receipts and delivery path. Partial JSON cannot execute, and attempts cannot concatenate. [TOOLS](TOOLS.md#agreed-automatic-recovery-and-dual-transport-contract) owns validated retry settings, original persisted job limits and cancellation. When `automatic_retries` is positive, it is the authoritative allowance, including eligible queue attempts; the starting trial value 2 allows three app HTTP attempts. Attempts are durable before dispatch and survive resume. Bounded ambiguous replay needs no routine manual settlement confirmation while remote state/cost remains unknown. Remote-result/status recovery, verified remote cancellation, native stream reconnection and exactly-once generation are not implemented. CURRENT_STATE/EVIDENCE own current offline and live verification.
