## OCR backend and packaging choices

Tesseract.js 6.0.1/core 6.1.2 with local chi_tra/eng 1.0.0 data is the selected OCR implementation. It returns text/TSV/blocks/confidence/positions and accepts page/region/DPI/PSM choices. Missing languages fail; low-confidence/empty output warns. Per-language preflight/hash/cold initialization precedes combined recognition. Recognition is local with no runtime language download. This establishes initialization, not accuracy.

Compatibility evidence: 6.0.1/core 6.1.2 initialized singly/jointly; 7.0.0/core 7.0.0 emitted misleading multilingual loading diagnostics with the same data despite cold single-language success. The compatible lock has a concrete reason; newest is not automatically best. OCR renders are scratch evidence, not replacement artwork. Native Tesseract/PyMuPDF OCR wrapper is inactive; the agent may choose other justified methods.

Bundled Node plus unpacked worker/WASM/data is the selected desktop packaging direction, not a verified installed app. PyInstaller backend inclusion, platform resources/lifecycle and app-stage script permissions need desktop evidence, outside the closed trial's scope. Shared finite recovery/dual transport have scoped offline/live evidence; arbitrary old-session restoration and general crash/migration infrastructure remain deferred.
